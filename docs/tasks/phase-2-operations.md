# Phase 2 교적 운영 구현

## 구현 항목

1. 사용자 데이터 범위: 전체 교회/조직(하위 포함 선택)/본인/없음. UI, 세션 무효화, 목록·상세·변경·가족 및 관계 필터.
2. CSV 이전: 필드 연결, 사전 오류·중복 후보, 원자적·멱등 실행, 권한·범위별 1회 내보내기, 수식 중화.
3. 모임·출석: 모임/회차, 수기·일괄 기록, 버전 충돌, 불변 변경 이력, 교회 시간대 기간 집계.
4. 새가족: 교회별 단계, 담당자·예정일, 완료·미완료·기한 경과, 단계 변경 이력.
5. 심방·목양: 교인/가족 대상 방문·연락·담당·후속 일정과 완료, 독립 메모 권한·정책·암호화·만료 파기.

정책은 ADR-006을 따른다. 기존 7개 migration을 변경하지 않고 008–012를 추가한다.
새 기능 권한은 기존 identity.manage 역할과 새 bootstrap 관리자에 추가한다. 다른 역할에는 자동 부여하지 않는다.
기존 사용자 범위는 ALL로 보존하고 API로 만드는 새 사용자는 NONE이다.

## 검증

`pnpm lint`, `pnpm typecheck`, `pnpm test`, `pnpm test:integration`, `pnpm build`.
DB 통합 검사는 격리된 임시 DB에서 migration/reset과 전체 업무·보안 경계를 검증한다.
`./scripts/verify-deployment.sh`로 clean 설치, 반복 배포, volume 보존, backup/restore와 overwrite 거부를 검증한다.
원격 PR CI의 verify/deployment job을 통과한 뒤 인계한다.

## 사용 흐름

- 관리자는 계정·권한에서 역할과 데이터 범위를 지정한다. 제한 사용자는 재로그인한다.
- 가져오기·내보내기에서 CSV 머리글을 연결하고 미리보기를 확인한 뒤 실행한다.
- 모임·출석에서 모임 정의 → 회차 → 교인 검색·선택 상태 저장 → 이력/기간 집계를 사용한다.
- 새가족에서 교회 단계를 먼저 설정하고 교인·담당자·예정일로 과정을 시작한다.
- 심방·목양에서 대상과 실제 일시·담당자·후속 예정일을 등록한다. 민감 메모는 기본 비활성이다.

## 후속 범위

XLSX, 대용량 비동기 처리, 자동 회차 생성, QR, 첨부파일, 실제 중복 병합, 알림 발송과 헌금·회계는 후속이다.
