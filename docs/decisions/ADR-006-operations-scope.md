# ADR-006: 교적 운영과 데이터 접근 범위

- 상태: Accepted
- 날짜: 2026-09-20

기능 권한과 사용자 데이터 범위를 분리한다. ALL/ORGANIZATIONS/SELF/NONE을 지원한다.
기존 사용자는 migration에서 ALL로 보존하며 새 사용자는 NONE이다. 최초 bootstrap 관리자만 ALL이다.
여러 담당 조직은 합집합이며 하위 조직은 해당 배정에서 명시적으로 포함한 경우만 확장한다.
현재 유효한 조직 소속으로 접근을 판단한다. 미소속 교인은 전체 교회 담당자만 보며,
SELF는 관리자가 연결한 교인만 볼 수 있다. 본인 범위 변경은 금지한다.
범위 변경은 교회 잠금, 감사, authVersion 증가와 세션 종료를 함께 처리한다.

범위는 DB 조회 조건에 pagination 전에 적용한다. 상세/변경은 같은 application 서비스를 사용한다.
가족에는 담당 교인이 있는 경우만 접근하며, 구성원과 수는 담당 교인만 반환한다.
제한 사용자는 가족 공통 연락처·주소를 받지 않는다. 가족/조직/직분 공유 구조의 변경과
교인 신규 등록, 교회 전체 감사 및 사용자 관리는 ALL 사용자만 가능하다.
교인 관계에는 상대 교인도 범위 내인 관계만 반환한다. 조직 이력은 담당 조직만 표시한다.
이전 시점의 가족 조회도 현재 담당 범위로 제한한다.

가져오기는 CSV, 사전 검증과 명시적 실행의 두 단계다. 중복 이름은 후보로 표시하며 자동 병합하지 않는다.
출석은 모임과 회차를 분리하고 수정 이력을 보존한다. 새가족 단계는 교회가 설정하며 교적 상태를
자동 변경하지 않는다. 심방은 메타데이터와 암호화된 메모를 분리한다. 민감 메모는 보존 정책이
명시적으로 설정되기 전에는 생성하지 않는다. 세부 정책과 API는 구현에 맞춰 이 문서에 추가한다.

## CSV 이전과 반출

첫 구현은 UTF-8 CSV, 500KB·500행 제한의 동기 처리다. 대용량 background job과 XLSX는 후속이다.
기본 열은 교인번호/이름/등록일/상태이며 CSV 머리글을 각각 연결한다. 연락처·주소는 PII 권한이 필요하다.
등록번호 중복과 검증 실패는 행 단위 오류, 같은 정규화 이름은 중복 후보로 제시한다. 후보는 자동 병합하지 않는다.
미리보기는 생성자에게 귀속되고 1시간 후 만료한다. 실행은 교회 잠금 안에서 모든 등록·최초 이력·감사를
한 transaction으로 저장한다. 같은 batch를 재실행하면 기존 완료를 반환한다. 완료 즉시 임시 행 본문을 비운다.
미리보기 이후 생긴 중복/설정 변경은 전체 실행을 취소한다.

내보내기는 별도 membership.export와 membership.read 권한이 필요하다. 작업은 생성자만 사용할 수 있고
10분 만료·1회 다운로드이며 실제 다운로드 시 현재 범위·PII 권한으로 다시 조회한다. 최대 500명이며
초과하면 검색/조직 필터를 좁혀야 한다. CSV 수식 접두어와 선행 제어 문자를 중화한다.
요청·다운로드·가져오기 실행은 본문 없이 감사한다. 만료한 임시 자료는 시작 시 및 매시간 정리한다.

## 모임·출석

Gathering은 반복 일정의 설명과 대상 조직을 저장하며 실제 일시는 GatheringSession에 저장한다.
회차 자동 생성/QR은 후속이다. 출석은 회차·교인별 한 행이며 version으로 덮어쓰기 충돌을 거부한다.
수기와 100명 이하 일괄 입력은 같은 transaction을 사용한다. 상태/입력 출처/수정자/버전은 불변 이력으로 남긴다.
조직 모임은 회차 당시 조직 소속도 검증한다. 미래 회차는 만들 수 있으나 출석은 현재 이후 회차에 기록하지 않는다.
조회·이력·최대 1년 집계는 현재 담당 범위를 적용한다. 일자 집계 경계는 교회 timezone을 사용한다.

## 새가족

교회별 단계의 이름·순서·사용·완료 여부를 설정한다. 교인당 정착 과정은 하나이며 version으로 변경한다.
단계, 담당자, 후속 예정일의 변경마다 당시 단계명을 복사한 불변 이력을 남긴다. 완료 단계로의 이동은
과정을 완료하고 진행 단계로 돌아오면 재개한다. 단계 설정 변경은 이미 완료된 과정을 소급 변경하지 않는다.
교적 상태는 자동 변경하지 않고 기존 교적 상태 변경 업무에서 별도로 처리한다.
담당자는 활성 계정이면서 대상 교인 접근 범위를 보유해야 한다. 제한 사용자는 담당자 선택 목록에서 본인만 본다.

## 목양 메타데이터와 제한 메모

대상은 교인 또는 가족 중 하나다. 가족 기록은 현재 구성원 전부가 담당 범위에 있을 때만 접근한다.
방문/전화/연락/면담의 실제 일시와 담당자, 후속 예정일, 완료 상태를 보존하며 변경 이력은 불변이다.

일반 care.read/write는 메모 본문 접근을 부여하지 않는다. 별도 care.notes 권한과 대상 범위가 모두 필요하다.
메모 작성자는 현재 담당자여야 하며 공개 범위는 작성자·현재 담당자 또는 작성자·지정 역할이다.
지정 역할은 작성자가 실제로 보유한 역할만 선택한다. 사용자 관리 권한은 다른 담당자의 메모 열람 권한이 아니다.
메모는 수정·삭제 대신 새 메모로 정정하며 조회/작성은 본문 없이 감사한다.

교회 관리자가 실제 확정한 정책 문서 위치/정책명과 1–3650일 보존기간을 입력하고 명시적으로 활성화해야 한다.
초기 정책과 기본 보존기간은 제공하지 않는다. 별도의 CARE_ENCRYPTION_KEY(64 hex)가 없으면 활성화를 거부한다.
본문은 AES-256-GCM으로 암호화한다. 보존기간은 생성 시 확정하고 정책 변경은 이후 메모에 적용한다.
만료 즉시 API에서 제외하고 시작 시 및 매시간 암호문을 null로 파기해 기술적 메타데이터와 파기 감사만 보존한다.
서버가 중단됐던 기간의 만료 메모도 다음 기동 시 정리하며 `pnpm care:purge`로 수동 파기할 수 있다.
정책 비활성화는 모든 메모 조회·생성을 중단하지만 원래 보존기간을 임의로 연장하거나 취소하지 않는다.
DB trigger는 만료 본문 파기 이외의 메모 수정·삭제를 거부한다. 백업의 보존·파기는 서버 운영 정책에 별도 반영한다.
첨부파일/만료 URL은 이번 단계의 범위 밖이다.

## 모듈 구성

OperationsModule 안에서 AttendanceService, NewcomerService, CareService가 각 aggregate를 담당한다.
공통 OperationsPolicy는 transaction·입력 날짜·인가를 제공한다. Registry의 데이터 이전은 같은 RegistryModule에
배치하여 교인 등록과 최초 이력의 불변식을 함께 유지한다. 외부 모듈은 Identity 공개 application 서비스를 사용한다.
