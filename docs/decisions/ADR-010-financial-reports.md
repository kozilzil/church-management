# ADR-010: 원장 기준 월별 재정보고서

- 상태: accepted
- 범위: 월별 보고서, 계정·기금별 대조, 원거래 연결, 집계 CSV

## 집계 기준

원장 `journal_entry`와 `journal_line`만 집계한다. 미게시 헌금, 미지급 지출 요청은 포함하지 않는다.
원래 분개를 지우거나 역분개된 원본을 제외하지 않는다. 각 분개를 해당 게시일에 반영한다.
기초는 시작일 이전 누계, 기간 금액은 시작일·종료일을 포함한다. 마감된 기간도 조회할 수 있다.
조회 기간은 1900년 이후 최대 366일이다. 첫 달과 마지막 달의 월별 행은 선택 날짜만 포함한다.

- 수입 = 수입 계정의 기간 대변 − 차변
- 지출 = 지출 계정의 기간 차변 − 대변
- 수지 차액 = 수입 − 지출
- 자산 증감 = 모든 자산 계정의 기간 차변 − 대변
- 기말 자산 = 기초 자산 + 자산 증감

자산 장부잔액은 현금·통장을 포함한 모든 자산이다. 실제 은행 잔액 대사는 아니다.
차입, 자산 간 이체, 기타 분개로 수지 차액과 자산 증감이 다를 수 있다.
계정별 잔액은 자산·지출의 경우 차변 − 대변, 나머지는 대변 − 차변이다.
연도 시작에 수입·지출 계정 잔액을 인위적으로 0으로 초기화하지 않는다. 누계 잔액과 기간 수입·지출을 구분한다.
원화 계산은 SQL numeric과 BigInt로 수행하며 API 집계 금액은 정수 문자열이다.

## 동일 조회 기준

보고서·거래 상세·CSV는 기존 재정 쓰기와 같은 교회별 advisory transaction lock을 사용한다.
최초 조회는 해당 교회의 최대 `journal_entry.created_xid`를 `ledgerVersion`으로 반환한다.
상세·내보내기는 해당 값 이하의 불변 원장만 사용한다. 늦게 게시된 과거 날짜 거래는 새로 조회해야 포함된다.
지원하는 모든 원장 게시 경로는 lock을 획득한 뒤 transaction ID를 부여받는다. DB 외부 직접 쓰기나
선행 transaction ID 할당을 도입하는 새 게시 경로는 이 계약을 재검토해야 한다.
이는 법적 확정 결산 문서나 저장된 보고서 스냅샷이 아니다. 원거래 상세와 미사용 기준정보는 현재 정보를 표시한다.
상세는 게시일·분개행 ID 순서로 50개씩 조회하고, cursor가 같은 필터·원장 기준에 포함되는지 검사한다.

## 권한과 개인정보

- `finance.report`: 교회 전체 집계와 보고서 기준정보 조회.
- `finance.report` + `finance.readall`: 집계에서 기간 원장 행 조회.
- 여기에 `offering.read` 또는 `expense.read`가 있을 때만 해당 원거래 링크를 반환한다.
- 실제 상세·증빙은 기존 권한 검사 API를 재사용한다.
- `finance.report` + `finance.export`: 집계 CSV. 최근 15분 인증, CSRF·Origin 검사. 운영에서는 MFA 필요.

교적 권한·개인 지출 참여 권한만으로는 교회 전체 보고서를 볼 수 없다. 기존 역할에 새 권한을 자동 부여하지 않는다.
집계와 원장 행에는 기부자·수령인·자유기재 설명을 포함하지 않는다. 조회·상세·내보내기를 감사하며 감사 로그에는
금액이나 이름을 넣지 않는다. 민감 응답은 private, no-store다.

## 출력과 후속 범위

CSV는 UTF-8 BOM과 CRLF를 사용하고 셀 따옴표·수식 시작 문자열을 처리한다. 화면과 같은 필터·원장 기준을 사용하며
집계만 포함한다. 파일에는 원화 정수 전체를 기록한다. Excel은 15자리 초과 숫자를 자동 변환할 수 있으므로
큰 금액은 가져오기 시 텍스트 열로 지정해야 한다. 전용 XLSX/PDF, 예산 편성·집행률, 계좌 대사, 확정 결산은 후속이다.
새 runtime dependency나 서비스는 추가하지 않는다. 조회용 원장 행 인덱스 2개와 권한 migration만 추가한다.
