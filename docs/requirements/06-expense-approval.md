# 지출 요청·결재·지급 요구사항

## 확정한 흐름

사용자 요청: 지출 요청 → 승인 결재 → 수동 지급 기록 → 회계 반영.
결재선은 요청자가 결재권한이 있는 교회 내 사용자 1–5명을 순서대로 선택한다.
사진·영수증·PDF 증빙을 요청서에 첨부하고 결재자가 열람한다.

DRAFT → IN_REVIEW → APPROVED → PAID. 반려하면 RETURNED, 수정 후 다시 제출한다.
DRAFT/RETURNED/IN_REVIEW/APPROVED에서 요청자가 사유와 함께 CANCELLED 처리할 수 있다.
승인 중 내용·결재선·증빙은 변경하지 않는다. 반려 재상신은 새 회차로 남긴다.

## 업무 규칙

- 요청 항목: 제목, 용도, 수령인 표시명, 정수 원화 금액, 비용 계정, 기금, 증빙 참조 및 첨부.
- 상신 시 증빙 참조 또는 첨부가 최소 하나 있어야 한다. 실제 계좌번호는 수집하지 않는다.
- 결재자는 활성 사용자이며 expense.approve 권한을 보유해야 한다. 본인/중복 지정 금지.
- 결재선은 상신 당시 순서대로 보존한다. 선행 승인 없이 후행 결재할 수 없다.
- 반려 사유 필수. 재상신 시 이전 승인 효력은 이어받지 않는다.
- 지급자는 요청자 및 현재 회차 결재자와 다른 사람이어야 한다.
- 승인된 전액을 한 번 지급한 사실만 기록한다. 분할 지급과 실제 은행 송금은 후속 범위다.
- 지급일, 지급 방식, 자산 계정, 중복되지 않는 지급 참조를 기록한다.
- 지급과 동시에 비용 차변/자산 대변의 균형 분개를 단일 트랜잭션으로 게시한다.
- 열린 회계기간에만 게시한다. 마감은 되돌리지 않는다. 잘못된 원장 기록은 열린 기간의 역분개로 정정한다.
- 역분개는 장부 정정이며 실제 송금 취소가 아니다. 원 지출은 PAID 상태를 유지하며 재지급하지 않는다.
- 낙관적 버전 검사, 교회별 쓰기 잠금, 지급 고유 제약으로 동시·반복 요청을 차단한다.

## 파일

- JPEG/PNG/PDF, 파일당 10 MiB, 요청서 현재 증빙 최대 10개.
- 확장자/브라우저 MIME만 신뢰하지 않고 파일 시그니처를 검사한다.
- 임의 파일명 대신 UUID 저장 키, SHA-256/크기 기록. 원본 이름은 안전한 표시명으로 정리한다.
- 파일은 인증 API에서만 다운로드한다. PDF는 다운로드로 제공하고 사진은 인증된 Blob으로 미리본다.
- 수정 가능한 요청서에서는 첨부를 제외할 수 있으나 이전 상신에 포함된 증빙 원본은 보존한다.
- 이 단계에서는 업로드 디스크 volume을 storage port 뒤에 둔다. 백업/복구 대상에 포함한다.
- 자동 증빙 파기/악성코드 검사 엔진/S3는 후속. 보존기간을 임의로 정하여 파일을 삭제하지 않는다.

## 권한

시스템 관리자는 finance.manage(설정/재정 역할 부여)만 받으며 재정 상세는 자동 열람하지 않는다.
expense.read는 본인 요청/본인이 결재선에 포함된 요청을 허용한다.
expense.pay는 승인/지급 상태의 요청을 추가 조회한다. finance.readall은 교회 전체 지출·원장 조회다.
expense.write/approve/pay, finance.manage/readall/close/reverse를 분리한다.
교적 담당 범위를 재정 접근 근거로 사용하지 않는다. 재정은 교회 및 업무 참여/별도 재정 권한으로 검사한다.

## 완료 기준

요청자 결재선 선택, 증빙 업로드/미리보기, 상신·순차 승인·반려·재상신·취소,
수동 지급과 균형 분개, 마감/역분개, 전체 이력까지 API/화면/DB/테스트로 검증한다.
교회 간 파일 접근, 자기 승인, 결재 순서 위반, 중복 지급, 마감 기간, 게시 원장 변경을 거부한다.

## 예산 통제 확장

요청서에 지급 예정 예산 연도를 필수로 입력하며 제출본에 보존한다. 상신·승인·지급 때 승인 예산과 다른 미지급 예약액을 확인한다.
WARN/BLOCK 정책, 예약 해제, 실제 지급 연도 일치 및 기존 NULL 연도 자료의 이행은 [ADR-012](../decisions/ADR-012-budget-approval-controls.md)를 따른다.
