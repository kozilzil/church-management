# 교인과 가족 요구사항

## Member

필수 최소 정보는 교회 내부 교인번호, 이름, 등록일, 현재 교적 상태다. 생년월일,
연락처, 주소, 성별 등은 교회의 실제 업무 필요성과 개인정보 정책이 확정된 항목만
선택적으로 저장한다.

### 주요 기능

- 교인 신규 등록 및 중복 후보 확인
- 기본 정보 수정
- 활성/비활성 및 교적 상태 변경
- 이름, 교인번호, 연락처 일부, 조직으로 검색
- 직분·소속·가족·상태 이력 조회
- 데이터 내보내기 권한 분리

### 상태 변경

상태 코드는 교회가 설정할 수 있어야 하며 시스템의 예시는 다음과 같다.

- NEWCOMER
- ACTIVE
- INACTIVE
- TRANSFERRED
- DECEASED

상태 변경에는 적용일, 이전/신규 상태, 사유, 처리자, 기록 시각을 남긴다. 미래 적용은
별도 요구사항이 생기기 전까지 허용하지 않는다.

## Household

Household은 가족 자체와 현재 가족 소속을 분리한다. 가족 구성원의 개인 연락처가
Household 연락처보다 우선할지 여부는 화면에서 명확히 표시한다.

### 규칙

- Member는 한 시점에 최대 하나의 활성 Household membership을 가진다.
- Household에는 0명 또는 1명의 대표자를 지정할 수 있다.
- 대표자는 해당 Household의 활성 구성원이어야 한다.
- 구성원 이동 시 기존 membership의 종료일과 신규 membership의 시작일을 기록한다.
- 활성 구성원이 있는 Household은 삭제할 수 없다.
- 부부, 부모, 자녀 등 관계는 방향과 유효기간을 가진 별도 relation으로 관리한다.

## 중복 처리

이름만으로 자동 병합하지 않는다. 중복 후보를 제시하되 실제 병합은 별도 권한과
확인 절차를 사용한다. 병합 작업은 감사 로그와 원본 식별자 mapping을 보존해야 한다.

## Acceptance criteria 요약

1. 새 Member 생성 시 상태 이력이 함께 생성된다.
2. Member를 Household에 배정하거나 이동할 수 있다.
3. 이동 전후 이력을 특정 날짜 기준으로 재구성할 수 있다.
4. 대표자 규칙과 활성 membership 중복이 DB와 application 양쪽에서 보호된다.
5. 조회 권한이 없는 민감 필드는 API 응답에 포함되지 않는다.
