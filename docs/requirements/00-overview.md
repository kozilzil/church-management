# 요구사항 개요

## 제품 목표

교회의 교적, 목양, 출석, 헌금, 회계 업무를 하나의 데이터 흐름으로 연결하되 담당자별
권한과 감사 가능성을 보장한다. 엑셀과 종이 문서에 흩어진 정보를 단계적으로 이전할
수 있어야 한다.

## 주요 사용자

| 사용자        | 주요 업무                                    |
| ------------- | -------------------------------------------- |
| 시스템 관리자 | 교회 설정, 사용자, 역할과 권한 관리          |
| 교역자        | 담당 교구 교인 조회, 심방, 새가족, 출석 확인 |
| 교적 담당자   | 교인·가족·직분·소속·증명서 관리              |
| 재정 담당자   | 헌금 입력, 검수, 분개, 예산·결산             |
| 감사자        | 재정·권한·변경 이력의 읽기 전용 검토         |
| 일반 교인     | 향후 본인 정보 확인과 제한적 수정 요청       |

## 핵심 용어

| 용어               | 정의                                                  |
| ------------------ | ----------------------------------------------------- |
| Member             | 교적에 등록된 개인                                    |
| Household          | 주소·연락처를 공유할 수 있는 가족/세대 단위           |
| Organization       | 교구, 구역, 부서, 위원회, 교회학교 등의 계층 조직     |
| Position           | 집사, 권사, 장로 등 교회가 정의하는 직분              |
| Membership status  | 등록, 새가족, 재적, 장기결석, 이명, 별세 등 교적 상태 |
| Offering batch     | 특정 예배/일자에 접수된 헌금의 검수 단위              |
| Posted transaction | 검수 후 회계 원장에 확정 반영된 변경 불가 거래        |

## 단계별 범위

### Phase 0 — 기반

- TypeScript 모노레포와 개발 환경
- PostgreSQL, migration, seed
- 공통 오류·로깅·테스트 기준
- 인증 및 최소 RBAC 골격

### Phase 1 — 교적 Core

- Member, Household
- Organization, Position
- 상태·가족·소속·직분 이력
- 검색, 목록, 상세, 기본 Audit

### Phase 2 — 교적 운영

- 새가족 정착 과정
- 출석과 모임
- 심방·상담 기록
- 데이터 가져오기/내보내기

### Phase 3 — 헌금

- 헌금 종류와 접수 배치
- 익명/기명 헌금
- 검수, 게시, 정정

### Phase 4 — 회계

- 계정과목과 복식부기
- 예산, 마감, 보고서
- 헌금에서 회계 분개 연결

### Phase 5 — 문서·통계

- 기부금영수증
- 교적 증명서와 요람용 자료
- Dashboard와 정형 보고서

## v1 비범위

- 급여와 인사 관리
- 온라인 예배 스트리밍
- 교회 홈페이지 CMS
- 카드/계좌 결제 대행
- 네이티브 모바일 앱
- 여러 교회를 위한 상용 SaaS 과금

## 공통 품질 기준

- 개인정보는 최소 수집하고 필드별 접근을 제한할 수 있어야 한다.
- 모든 변경 API는 사용자와 교회 범위를 확인해야 한다.
- 업무상 중요한 변경은 누가, 언제, 무엇을, 왜 변경했는지 추적한다.
- 운영 데이터는 hard delete보다 비활성화 또는 정정 이력을 사용한다.
- 목록과 검색은 10만 명 수준에서도 pagination을 전제로 설계한다.
