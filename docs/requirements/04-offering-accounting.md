# 헌금과 회계 요구사항

## Offering

헌금 접수와 회계 원장을 분리한다. 재정 담당자가 입력한 `OfferingBatch`를 검수하고
게시하면 헌금 레코드와 대응 회계 분개가 확정된다.

### Offering batch 상태

```text
DRAFT -> REVIEWED -> POSTED
   \        |
    -> CANCELLED
```

- DRAFT는 수정 가능하다.
- REVIEWED 이후 변경은 재검수가 필요하다.
- POSTED는 수정·삭제할 수 없으며 reversal로 정정한다.
- 기명 헌금은 Member와 연결할 수 있고 익명 헌금도 허용한다.
- 헌금 종류, 예배/접수일, 금액, 입력 출처를 기록한다.

## Accounting

- 복식부기 사용
- 계정과목은 자산, 부채, 순자산, 수익, 비용 유형을 가진다.
- 모든 JournalEntry의 차변·대변 합계는 동일해야 한다.
- 게시된 분개는 변경 불가다.
- 회계기간 마감 뒤 해당 기간 게시를 금지한다.
- 정정은 원거래 참조를 가진 reversal과 신규 거래로 수행한다.
- 예산은 원장과 분리하고 계정/부서/기간 단위로 관리한다.

## 개인정보와 권한

- 교역자가 교적을 볼 수 있다는 이유만으로 개인별 헌금액을 볼 수 없어야 한다.
- 개인별 헌금 조회, 일괄 내보내기, 기부금영수증 발급 권한을 각각 구분한다.
- 재정 보고서는 필요 시 기부자 식별 정보를 제거한 집계 형태로 제공한다.

## Acceptance criteria 요약

1. 불균형 분개는 application과 DB transaction 경계에서 게시되지 않는다.
2. POSTED 데이터의 update/delete API는 존재하지 않는다.
3. 정정 후 원거래와 reversal의 연결을 추적할 수 있다.
4. 회계기간 마감과 권한 검사가 모든 게시 경로에 적용된다.
